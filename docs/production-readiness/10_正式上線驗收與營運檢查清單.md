# 10｜正式上線驗收與營運檢查清單

> 版本：2026-06-02  
> 文件目的：提供正式部署前一天、上線當下、上線後觀察與事故處理的可執行清單。

---

## 1. 上線前一天

```text
□ 確認本次版本號
□ 確認部署內容
□ 確認 Git Tag / Commit
□ 確認資料庫備份
□ 確認回滾方案
□ 確認金流正式環境
□ 確認物流正式環境
□ 確認 DNS 與 TLS
□ 確認監控與告警
□ 確認負責人與聯絡方式
□ 確認 Swagger 正式環境管控
□ 確認 CORS 白名單
□ 確認 CSRF 防護
□ 確認 Rate Limiting
□ 確認 Health Check
□ 確認沒有 Production Secret 進 Git
```

□ 部署 Admin 前端
□ 執行資料庫變更

□ 檢查 API 健康狀態
□ 檢查前台首頁

□ 檢查商品查詢
□ 檢查加入購物車
□ 檢查訂單建立
□ 檢查付款流程

□ 檢查後台訂單查詢

## 3. 上線後一小時

```text
□ API 錯誤率正常
□ API 回應時間正常
□ 資料庫 CPU / Memory 正常
□ DB 連線數正常
□ Log 無大量錯誤
□ 金流 Callback 正常
□ 訂單數量合理
□ 後台可正常操作
□ 沒有大量登入失敗
□ 沒有大量 429 Rate Limit
□ 沒有大量 401 / 403 異常
□ 沒有付款狀態卡住
```

---

## 4. 上線後一天

```text
□ 備份任務成功
□ 沒有異常登入
□ 沒有大量 4xx / 5xx
□ 沒有付款狀態卡住
□ 沒有庫存異常
□ 稽核紀錄正常
□ 客服或營運回報已確認
□ 第三方金流與物流帳務初步核對
□ 前端錯誤追蹤沒有重大異常
□ 監控告警門檻需要時已微調
```

□ 檢查付款成功率

## 6. 事故處理基本流程

```text
1. 確認問題現象
2. 判斷影響範圍
3. 決定修復、降級或回滾
4. 保留 Log 與資料
5. 修復後重新驗證
6. 記錄事故原因
7. 補上預防措施
```

---

## 7. 常見事故處理方向

| 事故 | 優先處理 |
|---|---|
| 網站無法開啟 | 檢查 DNS、TLS、CDN、反向代理、API 健康狀態 |
| 登入大量失敗 | 檢查 Auth API、Cookie、CSRF、CORS、Rate Limit、DB |
| 付款 Callback 失敗 | 檢查金流簽章、事件 ID、PaymentTransactions、Log |
| 建立訂單失敗 | 檢查庫存保留、Transaction、DB 鎖定、錯誤 Log |
| 出貨扣庫異常 | 檢查 Shipment、InventoryTransactions、OrderStatusHistories |
| 大量 500 | 先看 TraceId、Exception、最近部署、資料庫狀態 |
| 大量惡意請求 | 啟用 WAF 規則、調整 Rate Limit、觀察正常使用者影響 |

---

## 8. 本章總結

上線不是部署完成就結束，而是要完成上線前、上線中、上線後的驗收。正式營運系統需要能觀察、能回滾、能追蹤、能復原。
