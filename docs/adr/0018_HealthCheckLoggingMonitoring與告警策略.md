# ADR-0018｜Health Check、Logging、Monitoring 與告警策略

- 狀態：已採納
- 日期：2026-06-02
- 關聯文件：`03_Program與Middleware安全管線.md`、`07_OWASP與API資安檢查清單.md`、`08_完整系統開發部署流程清單.md`

## 1. 背景與問題

正式啟用後，網站可能因資料庫連線失敗、外部金流異常、伺服器資源不足、錯誤部署或攻擊流量而中斷。若沒有健康檢查、日誌與告警，問題發生後只能等待使用者回報。

## 2. 決策

正式系統必須導入 Health Check、結構化 Logging、監控與告警。至少要能追蹤 API 存活、資料庫連線、登入失敗、付款失敗、系統錯誤與高頻異常請求。

## 3. 理由

- 正式部署不只要能啟動，還要能被監控與維運。
- 日誌可協助追蹤攻擊、錯誤與交易問題。
- Health Check 可供負載平衡器、反向代理或監控系統判斷服務狀態。

## 4. 實作要求

```text
□ 提供 /health/live 檢查應用程式存活
□ 提供 /health/ready 檢查 DB 與必要外部依賴
□ SystemErrorLogs 記錄後端錯誤摘要
□ UserLoginLogs 記錄登入成功與失敗
□ AdminActionLogs 記錄高風險後台操作
□ 日誌不得保存完整密碼、完整 Token、信用卡完整卡號
□ 監控 5xx、429、登入失敗、金流失敗、DB 連線錯誤
□ 重要異常需告警
```

## 5. 驗收檢查

```text
□ API 存活狀態可被檢查
□ DB 異常可被檢查
□ 500 錯誤可追蹤
□ 高頻登入失敗可追蹤
□ 後台重要操作可稽核
□ 敏感資料不會出現在日誌中
```
