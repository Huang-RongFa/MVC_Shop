# ADR-0013｜CORS 與可信任網域策略

- 狀態：已採納
- 日期：2026-06-02
- 關聯文件：`03_Program與Middleware安全管線.md`、`04_登入驗證Cookie權限與CSRF安全.md`、`05_前台與後台Vue正式部署流程.md`

## 1. 背景與問題

前端 Vue App 與後端 API 可能部署在不同網域或子網域。由於正式環境使用 Cookie Authentication，跨來源請求若設定不當，可能導致登入失敗或跨站請求風險。

## 2. 決策

正式環境 CORS 僅允許明確列出的前台與後台網域，不允許 `AllowAnyOrigin` 搭配 Credentials。

建議設定方向：

```text
Allowed Origins:
- https://www.example.com
- https://admin.example.com

AllowCredentials: true
Allowed Methods: 依 API 需求限制
Allowed Headers: Content-Type, X-CSRF-TOKEN 等必要 Header
```

## 3. 理由

- Cookie 驗證需允許 Credentials，但不能開放任意來源。
- CORS 是瀏覽器層級的跨來源控制，不可當作唯一授權機制。
- 後端仍必須檢查 Authentication、Authorization、CSRF 與資料擁有者。

## 4. 實作要求

```text
□ Development 可允許 localhost:5173 / localhost:5174
□ Staging / Production 只允許正式指定網域
□ 不使用 AllowAnyOrigin + AllowCredentials
□ CORS Middleware 順序必須在 Authentication / Authorization 前
□ 寫入型 API 仍需 CSRF 防護
□ 後台 API 仍需 Role / Permission
```

## 5. 驗收檢查

```text
□ 非白名單網域無法成功跨來源呼叫 API
□ 白名單前端可帶 Cookie 呼叫受保護 API
□ 未登入仍回 401
□ 權限不足仍回 403
□ CORS 未被誤用為授權機制
```
