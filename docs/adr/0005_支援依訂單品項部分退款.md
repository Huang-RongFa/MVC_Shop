# ADR-0005｜支援依訂單品項部分退款

- 狀態：已採納
- 日期：2026-06-02
- 關聯文件：`06_RESTfulAPI前後台API與交易流程.md`、`02_後端分層Repository與Service.md`

## 1. 背景與問題

真實電商售後情境不一定是整張訂單退款。常見情況包含單一品項缺貨、部分商品瑕疵、部分數量退貨、折扣分攤後退款或客服補償。若只支援整筆退款，售後流程會過於僵硬。

## 2. 決策

退款流程同時支援整筆訂單退款與依訂單品項的部分退款，並保留退款主檔與退款明細。

```text
Refunds：退款主檔
RefundItems：退款品項、數量、金額、原因
```

## 3. 理由

- 符合真實客服與售後作業。
- 可追蹤每個品項、數量與金額的退款原因。
- 有利於折扣、會計、金流與稽核紀錄。
- 避免為了部分退款而強迫取消整張訂單。

## 4. 實作要求

```text
□ RefundService 必須檢查可退款金額
□ 退款金額不得超過已付款金額扣除已退款金額
□ 部分退款必須對應 OrderItems
□ 退款必須寫入 Refunds 與 RefundItems
□ 退款成功需更新付款或訂單的退款狀態
□ 金流退款 Callback 必須驗簽與冪等處理
□ 退款操作必須寫入 AdminActionLogs 或 AuditLogs
```

## 5. 影響與取捨

| 面向 | 影響 |
|---|---|
| 優點 | 售後彈性高，符合正式營運情境 |
| 成本 | 退款計算需處理折扣分攤與已退款紀錄 |
| 風險 | 若沒有檢查可退款金額，可能超額退款 |

## 6. 驗收檢查

```text
□ 可建立整筆退款
□ 可建立部分品項退款
□ 不可超過可退款金額
□ 重複 Callback 不會重複退款
□ 退款紀錄可供客服、會計與稽核查詢
```
