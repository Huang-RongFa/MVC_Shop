# ADR-0012｜正式部署環境分離策略

- 狀態：已採納
- 日期：2026-06-02
- 關聯文件：`08_完整系統開發部署流程清單.md`、`09_常用指令與安全檔案模板.md`

## 1. 背景與問題

專案需要一邊學習、一邊部署與正式啟用。若開發、測試與正式環境混用同一組資料庫、Cookie、CORS、金流或機密，容易發生測試資料污染正式資料、Debug 設定外洩或錯誤串接正式金流。

## 2. 決策

至少區分以下環境：

```text
Development：本機開發
Staging：正式上線前測試
Production：正式營運
```

每個環境必須有獨立設定：

```text
Connection String
Cookie Name / Domain / Secure Policy
CORS Allowed Origins
金流與物流金鑰
Log Level
Swagger 開放策略
資料庫備份策略
```

## 3. 理由

- 正式部署不能使用本機開發設定。
- Staging 可先驗證正式網域、HTTPS、Cookie、CORS 與金流測試流程。
- 環境分離可降低誤操作正式資料的風險。

## 4. 實作要求

```text
□ 使用 appsettings.Development.json / Staging / Production 分離設定
□ 正式機密使用環境變數、User Secrets、Secret Manager 或 Key Vault
□ appsettings.Production.json 不上傳公開 Git
□ Production 關閉詳細錯誤
□ Production 不公開未授權 Swagger
□ Staging 盡量模擬 Production 設定
□ 部署前先完成資料庫備份
```

## 5. 驗收檢查

```text
□ 本機、測試、正式資料庫不同
□ 正式環境沒有 Debug Stack Trace
□ 正式 CORS 僅允許正式網域
□ 正式 Cookie 使用 Secure
□ 正式金鑰不在 Git 紀錄中
```
