# ADR-0017｜資料庫備份、還原與遷移策略

- 狀態：已採納
- 日期：2026-06-02
- 關聯文件：`01_資料庫與EFCore正式對應.md`、`08_完整系統開發部署流程清單.md`、`09_常用指令與安全檔案模板.md`

## 1. 背景與問題

正式電商系統的資料庫保存會員、訂單、付款、庫存、優惠與稽核資料。若部署前沒有備份，或從未測試還原，系統發生錯誤時即使有程式碼也無法恢復營運資料。

## 2. 決策

正式環境必須建立資料庫備份、還原演練與資料庫結構變更策略。資料庫結構以已確認的 MSSQL Script / Migration 流程為準，不得手動任意修改正式資料表後不留紀錄。

## 3. 理由

- 備份不等於可還原，必須定期測試。
- 電商交易資料是核心資產。
- Schema 變更需要可追蹤、可回滾或至少可補救。

## 4. 實作要求

```text
□ Production 部署前先備份資料庫
□ 定期全備份與必要的差異 / 交易記錄備份
□ 定期測試還原到非正式環境
□ Migration 或 SQL Script 需版本管理
□ 高風險 Schema 變更需先在 Staging 測試
□ 不在正式環境直接試錯 ALTER TABLE
□ 備份檔需保護權限與加密保存
□ 還原流程需有文件
```

## 5. 驗收檢查

```text
□ 可以說明最近一次備份時間
□ 可以說明最近一次還原測試結果
□ 部署前有備份紀錄
□ Schema 變更有版本紀錄
□ 備份檔未公開暴露
```
