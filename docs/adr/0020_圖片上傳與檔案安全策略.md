# ADR-0020｜圖片上傳與檔案安全策略

- 狀態：已採納
- 日期：2026-06-02
- 關聯文件：`05_前台與後台Vue正式部署流程.md`、`07_OWASP與API資安檢查清單.md`

## 1. 背景與問題

電商系統通常需要商品圖片、分類圖片、活動圖片與可能的售後附件。若檔案上傳沒有安全限制，可能被上傳惡意檔案、超大檔案拖垮伺服器、偽裝副檔名或造成 XSS / 任意檔案存取風險。

## 2. 決策

圖片與檔案上傳必須採白名單、大小限制、重新命名、隔離儲存與權限檢查。正式環境不允許使用者任意上傳可執行檔或直接控制儲存路徑。

## 3. 理由

- 檔案上傳是常見攻擊面。
- 商品圖片屬於公開資源，但上傳操作屬於後台高權限操作。
- 檔案名稱、MIME Type 與副檔名都不能單獨信任。

## 4. 實作要求

```text
□ 僅允許必要副檔名，例如 jpg、jpeg、png、webp
□ 檢查 MIME Type 與檔案內容特徵
□ 限制單檔大小與總容量
□ 檔名由系統重新產生，不信任原始檔名
□ 不允許前端指定伺服器儲存路徑
□ 上傳目錄不得執行程式碼
□ 圖片 URL 回傳公開路徑，不回傳伺服器實體路徑
□ 後台上傳需驗證權限並寫入操作紀錄
□ 可疑上傳需記錄並拒絕
```

## 5. 驗收檢查

```text
□ 上傳 exe / js / html 會被拒絕
□ 超過大小限制會被拒絕
□ 檔案名稱不可路徑穿越
□ 商品圖片可正常讀取
□ 上傳操作有權限與稽核紀錄
```
