# ADR-0003｜下單保留庫存並於出貨扣除實際庫存

- 狀態：已採納
- 日期：2026-06-02
- 關聯文件：`01_資料庫與EFCore正式對應.md`、`02_後端分層Repository與Service.md`、`06_RESTfulAPI前後台API與交易流程.md`

## 1. 背景與問題

電商訂單流程中，顧客下單、付款、備貨、出貨並不是同一個瞬間完成。若下單時直接扣除實際庫存，付款失敗、取消訂單或逾期未付款時會讓庫存回補流程變複雜；若完全不保留庫存，則可能出現超賣。

## 2. 決策

訂單建立時先建立保留庫存，實際庫存只在確認出貨時扣除。

```text
建立訂單
  ↓
建立 OrderItems
  ↓
建立 InventoryReservations
  ↓
付款成功進入 Paid
  ↓
建立出貨資料
  ↓
確認出貨時扣除 InventoryStocks
  ↓
寫入 InventoryTransactions
```

## 3. 理由

- 可降低付款前超賣風險。
- 出貨前取消訂單時，只需釋放保留庫存。
- 實際庫存扣除時間與商品離倉時間一致。
- 符合 `InventoryReservations` 與 `InventoryTransactions` 的資料模型。

## 4. 實作要求

```text
□ 建立訂單、訂單明細、保留庫存必須使用 Transaction
□ 保留庫存不得讓可售數量變成負數
□ 取消訂單必須釋放保留庫存
□ 付款失敗或逾期未付款必須釋放保留庫存
□ 出貨確認時才扣除實際庫存
□ 每次庫存異動必須寫入 InventoryTransactions
□ 後台手動調整庫存必須寫入 AdminActionLogs 或 AuditLogs
```

## 5. 影響與取捨

| 面向 | 影響 |
|---|---|
| 優點 | 可兼顧防超賣與取消訂單彈性 |
| 成本 | 庫存查詢需計算實際庫存、保留庫存與可售庫存 |
| 風險 | 若保留庫存沒有過期釋放，會造成庫存被長期占用 |

## 6. 驗收檢查

```text
□ 下單成功會建立 InventoryReservations
□ 下單失敗會回滾 Orders / OrderItems / Reservations
□ 取消訂單會釋放保留庫存
□ 出貨確認才扣 InventoryStocks
□ 庫存異動紀錄可追蹤原因與操作者
```
