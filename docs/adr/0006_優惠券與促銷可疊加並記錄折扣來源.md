# ADR-0006｜優惠券與促銷可疊加並記錄折扣來源

- 狀態：已採納
- 日期：2026-06-02
- 關聯文件：`06_RESTfulAPI前後台API與交易流程.md`、`01_資料庫與EFCore正式對應.md`

## 1. 背景與問題

正式電商常同時存在優惠券、滿額折扣、商品促銷、會員活動與免運優惠。若每張訂單只能有一筆折扣，雖然簡單，但無法支援真實行銷活動；若可疊加但不記錄來源，客服、退款、會計與稽核會無法還原當時折扣計算。

## 2. 決策

優惠券與促銷可以疊加，但每一筆套用到訂單的折扣都必須寫入 `OrderDiscounts`。

折扣來源至少需能區分：

```text
Coupon
Promotion
ManualAdjustment
ShippingDiscount
MemberDiscount
```

## 3. 理由

- 保留行銷彈性。
- 可還原訂單當下折扣計算。
- 可支援部分退款時的折扣分攤。
- 有利於客服查詢、會計對帳與稽核。

## 4. 實作要求

```text
□ CouponService 負責優惠券驗證與使用次數限制
□ PromotionService 負責促銷規則判斷
□ OrderService 建立訂單時寫入 OrderDiscounts
□ 前端不可自行決定折扣金額
□ 後端必須重新計算商品價格、促銷與優惠券
□ 取消訂單或退款時需考慮優惠券使用紀錄與折扣分攤
□ 折扣規則異動需保留訂單當下折扣結果
```

## 5. 影響與取捨

| 面向 | 影響 |
|---|---|
| 優點 | 支援正式行銷活動與稽核追蹤 |
| 成本 | 折扣計算與退款分攤較複雜 |
| 風險 | 若疊加規則沒有明確優先順序，可能造成折扣錯誤 |

## 6. 驗收檢查

```text
□ 一張訂單可同時套用優惠券與促銷
□ 每筆折扣都寫入 OrderDiscounts
□ 折扣金額由後端計算
□ 前端竄改折扣金額不會生效
□ 退款時可追蹤折扣來源
```
