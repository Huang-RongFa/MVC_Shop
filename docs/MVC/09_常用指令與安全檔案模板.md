# 09｜常用指令與安全檔案模板

## 1. 建立方案與專案

```bash
mkdir MySystem
cd MySystem

dotnet new sln -n MySystem

dotnet new webapi -n MySystem.Api
dotnet new classlib -n MySystem.Domain
dotnet new classlib -n MySystem.Application
dotnet new classlib -n MySystem.Infrastructure

dotnet sln add MySystem.Api
dotnet sln add MySystem.Domain
dotnet sln add MySystem.Application
dotnet sln add MySystem.Infrastructure
```

用途：建立後端分層專案，讓 API、商業邏輯、Entity 與資料存取分開管理。

---

## 2. 專案參考

```bash
dotnet add MySystem.Api reference MySystem.Application
dotnet add MySystem.Api reference MySystem.Infrastructure

dotnet add MySystem.Application reference MySystem.Domain

dotnet add MySystem.Infrastructure reference MySystem.Domain
dotnet add MySystem.Infrastructure reference MySystem.Application
```

用途：設定專案之間可以互相使用的方向。

---

## 3. 安裝 NuGet 套件

```bash
dotnet add MySystem.Infrastructure package Microsoft.EntityFrameworkCore.SqlServer
dotnet add MySystem.Infrastructure package Microsoft.EntityFrameworkCore.Design
```

若使用 FluentValidation、Health Checks、OpenAPI 或其他套件，請依實際需求安裝。

Cookie Authentication 通常由 ASP.NET Core 共用框架提供，不一定需要另外安裝 NuGet；重點是在 `Program.cs` 註冊 Authentication 與 Cookie 設定。

---

## 4. EF Core 指令

若之後採用 Code First：

```bash
dotnet ef migrations add InitialCreate -p MySystem.Infrastructure -s MySystem.Api
dotnet ef database update -p MySystem.Infrastructure -s MySystem.Api
```

如果資料庫已經依 `docs/MSSQL/11_mssql_create_table_script.sql` 建好，建議先不要急著讓 Migration 重建資料庫。可以先完成 Entity 與 DbContext 對應，確認查詢正常。

---

## 5. User Secrets 指令

本機開發不要把連線字串與密鑰寫入 Git。

```bash
cd MySystem.Api

dotnet user-secrets init

dotnet user-secrets set "ConnectionStrings:DefaultConnection" "Server=localhost;Database=EcommerceBackendDB;Trusted_Connection=True;TrustServerCertificate=True;"
dotnet user-secrets set "Auth:CookieSecret" "replace-with-development-secret"
dotnet user-secrets list
```

正式環境請使用 Environment Variables、Key Vault、Secret Manager 或主機提供的安全機密管理。

---

## 6. NuGet 套件弱點檢查

```bash
dotnet list package --vulnerable --include-transitive
```

建議部署前執行，並把結果納入檢查紀錄。

## 7. Vue 專案建立

建議前台與後台分開建立。

```bash
mkdir frontend
cd frontend

npm create vue@latest storefront
cd storefront
npm install
npm install axios bootstrap sweetalert2 vue-router pinia
npm run dev
```

後台：

```bash
cd ../
npm create vue@latest admin
cd admin
npm install
npm install axios bootstrap sweetalert2 vue-router pinia
npm run dev
```

---

## 8. npm 套件弱點檢查

```bash
npm audit
npm audit fix
```

注意：`npm audit fix --force` 可能造成破壞性升級，正式專案不要未測試就直接使用。

## 9. 後端啟動

```bash
dotnet run --project MySystem.Api
```

用途：啟動 ASP.NET Core Web API，提供 API 測試。

---

## 10. 前端 Build

```bash
cd frontend/storefront
npm run build

cd ../admin
npm run build
```

Build 後檢查：

```text
□ API Base URL 是否為正式 API
□ 前端產物是否不包含機密
□ dist 可被 Web Server 正確提供
```

## 11. appsettings.json 範本

開發版範例：

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Server=localhost;Database=EcommerceBackendDB;Trusted_Connection=True;TrustServerCertificate=True;"
  },
  "Auth": {
    "CookieName": "__Host-MySystemAuth",
    "ExpireMinutes": 60
  },
  "Cors": {
    "AllowedOrigins": [
      "http://localhost:5173",
      "http://localhost:5174"
    ]
  },
  "AllowedHosts": "*"
}
```

正式環境不要把連線字串、Cookie / Token 簽章金鑰、金流密鑰、物流 API Key 放在 Git。

---

## 12. .env.production 範本

前端 `.env.production` 只能放公開設定：

```env
VITE_API_BASE_URL=https://api.example.com
```

不可放：

```text
資料庫密碼
JWT 簽章金鑰
Cookie Secret
金流密鑰
SMTP 密碼
```

## 15. API 測試順序

```text
1. 確認 API 專案可啟動
2. 確認 Swagger 在開發環境可開啟
3. 確認 DbContext 可連 MSSQL
4. 測試 Storefront Auth Login
5. 測試 Cookie 是否成功設定
6. 測試 CSRF Token 流程
7. 測試 /api/storefront/auth/me
8. 測試 Admin Auth Login
9. 測試 /api/admin/auth/me
10. 測試 Storefront Products / Cart / Orders API
11. 測試 Admin Users / Roles 權限 API
12. 測試 Admin Products / Inventory / Orders API
13. 測試 Payments / Shipments / Refunds 流程 API
14. 測試 Coupons / Promotions 優惠 API
15. 測試 Audit Logs 查詢 API
16. 測試沒有登入狀態是否 401
17. 測試沒有權限是否 403
18. 測試 Rate Limiting 是否回 429
19. 測試 Production 是否不顯示詳細錯誤
```
