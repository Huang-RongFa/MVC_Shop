# 00｜總覽與正式上線架構

## 1. 文件定位

本文件定義本專案的整體技術方向。此專案不是教學用單表 CRUD，也不是只供本機展示的範例，而是一套準備正式部署的交易型電商系統。

核心架構如下：

```text
Storefront Vue App
  ↓
前台 API / JSON
  ↓
ASP.NET Core Web API 模組化單體
  ↓
Service / Repository / EF Core
  ↓
共用 MSSQL Database
  ↑
Service / Repository / EF Core
  ↑
後台 API / JSON
  ↑
Admin Vue App
```

正式上線時，系統必須同時考慮：

```text
功能正確性
資料一致性
權限控管
資安防護
錯誤處理
日誌與稽核
備份與復原
監控與告警
部署與回滾
```

---

## 2. 架構名稱

建議正式名稱：

```text
ASP.NET Core Web API 模組化單體 + 共用 MSSQL + Storefront Vue App + Admin Vue App
```

本階段不建議直接拆微服務。理由：

| 選項 | 優點 | 風險 | 建議 |
|---|---|---|---|
| 模組化單體 | 容易部署、交易一致性較好、學習成本較低 | 模組邊界要靠紀律維持 | 本專案優先採用 |
| 微服務 | 每個服務可獨立擴充 | 部署、分散式交易、監控、網路安全複雜度高 | 等系統成熟後再評估 |

---

## 3. 正式部署目標

正式部署不是只把網站放到主機上，而是要讓網站在真實使用者環境下可以穩定、安全、可追蹤地運作。

最低部署目標：

```text
□ 前台可瀏覽商品、加入購物車、登入、建立訂單
□ 後台可管理商品、庫存、訂單、付款、出貨、退款、優惠與稽核
□ API 只能被允許的前端來源呼叫
□ 登入使用 HttpOnly Secure Cookie
□ 重要操作有 Role / Permission 檢查
□ 建立訂單、付款、出貨、退款使用 Transaction
□ 錯誤不暴露 Stack Trace、SQL、檔案路徑
□ 有健康檢查端點
□ 有系統錯誤紀錄與後台操作紀錄
□ 有資料庫備份與還原流程
□ 有套件弱點檢查與部署前檢查
```

---

## 4. 系統主要模組

| 系統模組 | 主要資料表 | 後端責任 | 上線風險重點 |
|---|---|---|---|
| 帳戶與權限 | Users, Roles, UserRoles, Permissions, RolePermissions, UserLoginLogs | 登入、角色、權限、登入紀錄 | 暴力破解、越權、Cookie 竊用 |
| 商品目錄 | ProductCategories, Products, ProductSkus, ProductImages, ProductAttributes, ProductAttributeValues | 商品、分類、SKU、圖片、規格 | 價格被竄改、未授權上下架 |
| 庫存 | Warehouses, InventoryStocks, InventoryTransactions, InventoryReservations | 倉庫、庫存量、保留庫存、出貨扣庫 | 超賣、負庫存、併發更新 |
| 購物車與訂單 | ShoppingCarts, ShoppingCartItems, Orders, OrderItems, OrderStatusHistories | 購物車、建立訂單、狀態流轉 | 訂單狀態亂跳、資料只寫一半 |
| 付款、物流與退款 | Payments, PaymentTransactions, Shipments, ShipmentItems, Refunds, RefundItems | 金流回呼、出貨、退款 | 回呼重送、偽造付款、退款超額 |
| 優惠與促銷 | Coupons, CouponUsages, Promotions, PromotionProducts, OrderDiscounts | 優惠券、促銷、折扣紀錄 | 重複使用、折扣超額、規則繞過 |
| 稽核與系統紀錄 | AuditLogs, AdminActionLogs, SystemErrorLogs | 資料異動、後台操作、錯誤紀錄 | 無法追蹤事故、紀錄洩漏敏感資訊 |

## 5. 信任邊界

正式系統一定要先畫出信任邊界。

```text
使用者瀏覽器：不可信任
前端程式碼：不可信任，可被使用者修改
API Request：不可信任
Controller：只做入口與基本驗證
Service：執行真正權限與商業規則
Repository / DbContext：資料存取
MSSQL：資料真實來源
第三方金流 / 物流：外部不完全可信任，需驗簽與冪等處理
```

不可相信的資料：

```text
□ 前端傳來的 UserId
□ 前端傳來的 Role / Permission
□ 前端傳來的商品價格
□ 前端傳來的折扣金額
□ 前端傳來的訂單狀態
□ 金流回呼中未驗簽的資料
□ 查詢排序欄位、篩選欄位、分頁大小
```

## 6. 每一層負責的事情

| 層級 | 負責內容 | 不應該做的事 |
|---|---|---|
| Storefront App | 商品瀏覽、購物車、結帳、會員訂單 | 不保存高權限 Token、不決定價格 |
| Admin App | 後台操作介面、角色化選單 | 不當成真正權限來源 |
| Controller | 接收 Request、回 HTTP Status Code | 不寫複雜商業流程、不直接操作 DbContext |
| Service | 商業流程、權限判斷、交易控制、稽核觸發 | 不處理前端 UI 細節 |
| Repository | 查詢與儲存資料 | 不決定業務規則 |
| DbContext | EF Core 與 MSSQL 連線 | 不直接暴露給 Controller |
| DTO | API 輸入輸出模型 | 不等於 Entity |
| Entity | 對應資料表與關聯 | 不直接回傳前端 |

## 8. 環境分離

至少分成下列環境：

| 環境 | 用途 | 注意事項 |
|---|---|---|
| Local | 個人開發 | 可用測試資料，不可使用正式金鑰 |
| Development | 團隊整合測試 | 可開 Swagger，但不可外公開放 |
| Staging | 上線前驗收 | 使用接近正式環境的設定 |
| Production | 正式服務 | 嚴格機密管理、監控、備份、告警 |

正式環境不可使用：

```text
AllowAnyOrigin
DeveloperExceptionPage
測試用金流密鑰
預設管理員密碼
公開 Swagger
明文連線字串
未限制的資料庫帳號
```

## 9. 正式上線資安基準

```text
□ HTTPS Only
□ HSTS 規劃
□ CORS 限制白名單網域
□ Cookie 設定 HttpOnly / Secure / SameSite
□ Cookie 驗證搭配 CSRF 防護
□ 後台登入加入 Rate Limiting / Lockout
□ 後台管理員規劃 MFA
□ API 以 Role / Permission / Resource Ownership 檢查權限
□ API 回傳 DTO，不回傳 Entity
□ ProblemDetails 或統一錯誤格式
□ Health Check 不暴露敏感細節
□ NuGet 與 npm 套件弱點掃描
□ 機密使用 User Secrets / Environment Variables / Key Vault
□ 部署前資料庫備份
□ 上線後檢查登入、下單、付款、出貨、退款流程
```

---

## 10. 本章總結

本專案應以「可正式部署的模組化單體電商系統」作為共同語言。學習時可以逐步完成，但每一階段都要保留正式上線的安全邊界、資料一致性、監控與部署檢查，不要先寫成教學 CRUD 再事後補救。
