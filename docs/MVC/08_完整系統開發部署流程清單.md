# 08｜完整系統開發與部署流程清單

## 1. 本章目的

本章整理從本機開發到正式部署的完整流程。你的目標是一邊學習、一邊部署、一邊正式啟用，因此流程不能只停在本機 Swagger 測試，而要加入正式上線、資安、監控、備份與回滾。

---

## 階段 0：確認架構與環境

```text
□ 確認採用 ASP.NET Core Web API 模組化單體
□ 確認共用 MSSQL Database
□ 確認前端拆成 Storefront App 與 Admin App
□ 確認前台 API 與後台 API 分界
□ 確認正式登入以 HttpOnly Secure Cookie 為主
□ 確認部署環境：Local / Staging / Production
□ 確認正式網域規劃
□ 確認 HTTPS 憑證取得方式
```

---

## 階段 1：確認資料庫基礎

```text
□ 確認 MSSQL Database 已建立
□ 確認 11_mssql_create_table_script.sql 已執行
□ 確認 Users / Roles / Products / Orders 等主要資料表存在
□ 確認 PK、FK、UK、CK、Index 已建立
□ 確認 Program.cs 或測試程式可連上資料庫
□ 確認測試資料可查詢
□ 確認正式 DB 帳號採最小權限
□ 確認資料庫備份與還原流程
```

## 階段 2：建立後端專案結構

```text
□ 建立 MySystem.Api
□ 建立 MySystem.Domain
□ 建立 MySystem.Application
□ 建立 MySystem.Infrastructure
□ 設定專案參考

□ DTOs 分成 Storefront 與 Admin 邊界
□ 建立 Extensions 管理 DI 註冊

```

建議責任：

```text
Api：Controller、Middleware、Filter、Program.cs
Application：Service、DTO、Interface、Validator、PermissionChecker
Domain：Entity、Enum、Business Rule、Domain Exception
Infrastructure：DbContext、Repository、Transaction、外部服務
```

## 階段 5：建立帳戶、Cookie、CSRF 與權限

```text
□ AuthController
□ AuthService
□ UserService
□ RoleService
□ PasswordHasher
□ Cookie Authentication
□ Claims / Role / Permission
□ UserLoginLogs
□ CSRF Token 取得端點
□ 寫入型 API 驗證 CSRF
□ Program.cs 設定 Authentication / Authorization
□ 登入 API 設 Rate Limiting
□ 後台管理員規劃 MFA
```

驗收：

```text
□ 可以登入
□ 登入成功取得 HttpOnly Secure Cookie
□ Cookie 可呼叫受保護 API
□ 寫入型 API 沒有 CSRF Token 會失敗
□ 沒有登入狀態回傳 401
□ 權限不足回傳 403
□ 登入紀錄寫入 UserLoginLogs
□ 多次登入失敗會限制或鎖定
```

## 本章總結

一邊學習一邊部署是可行的，但每個階段都要保留正式上線標準。不要等功能全部完成才補資安；登入、權限、CSRF、交易、日誌、備份與監控應從第一版 MVP 就開始納入。
