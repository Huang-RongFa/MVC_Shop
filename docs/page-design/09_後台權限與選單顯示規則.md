# 09｜後台權限與選單顯示規則

## 1. 核心原則

後台頁面不是登入就全部可看，而是依 Role / Permission 顯示對應功能。

```text
登入驗證：確認你是誰
授權檢查：確認你可以做什麼
```

---

## 2. 常見角色

```text
Admin       系統管理員
Manager     營運主管
Staff       一般員工
Customer    前台會員，不能進後台
```

---

```text
Dashboard.Read

Promotions.Manage
Messages.Read
AuditLogs.Read
Settings.Manage
```

---

## 4. 選單顯示規則

| 選單 | 權限 |
|---|---|
| Dashboard | `Dashboard.Read` |
| 數據分析 | `Analytics.Read` |
| 使用者管理 | `Users.Manage` |
| 角色權限 | `Roles.Manage` |
| 商品管理 | `Products.Read` |
| 庫存管理 | `Inventory.Read` |
| 庫存調整 | `Inventory.Adjust` |
| 訂單管理 | `Orders.Read` |
| 付款管理 | `Payments.Read` |
| 出貨管理 | `Shipments.Manage` |
| 退款管理 | `Refunds.Manage` |
| 優惠券 | `Coupons.Manage` |
| 促銷活動 | `Promotions.Manage` |
| 訊息 / 通知 | `Messages.Read` |
| 稽核紀錄 | `AuditLogs.Read` |
| 系統設定 | `Settings.Manage` |

---

## 5. Razor 顯示範例

```razor
@if (User.HasClaim("Permission", "Products.Read"))
{
    <a asp-controller="AdminProducts" asp-action="Index" class="nav-link">
        商品管理
    </a>
}
```

高風險按鈕：

```razor
@if (User.HasClaim("Permission", "Refunds.Manage"))
{
    <button class="btn btn-primary">建立退款</button>
}
```

---

## 6. 後端仍須檢查

即使前端沒有顯示按鈕，使用者仍可能直接呼叫 URL 或 API。

所以必須：

```text
□ Controller 使用 [Authorize]
□ Controller 或 Policy 檢查 Permission
□ Service 再檢查高風險資料權限
□ 重要操作寫入 AdminActionLogs 或 AuditLogs
```

---

## 7. Customer 不得進入後台

後台登入成功後要檢查：

```text
UserType != Customer
```

如果 `Customer` 嘗試進入 `/Admin`：

```text
□ 未登入：導向 Admin/Login
□ 已登入但不是 Admin / Staff：回傳 403 或導向無權限頁
```

---

## 8. 本章總結

後台選單顯示是使用者體驗，不是資安本體。真正安全必須依靠 Controller、Authorization Policy、Service 權限檢查與稽核紀錄。
