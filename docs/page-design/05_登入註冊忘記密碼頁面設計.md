# 05｜登入、註冊與忘記密碼頁面設計

## 1. 頁面來源

登入頁可參考 `login.html` 的 Login Card、主題切換與表單樣式。

但正式系統要拆成：

```text
Views/Account/Login.cshtml          前台會員登入
Views/Account/Register.cshtml       前台會員註冊
Views/Account/ForgotPassword.cshtml 忘記密碼
Views/Admin/Login.cshtml            後台管理登入
```

---

## 2. 前台會員登入

欄位：

```text
Email 或帳號
密碼
記住我
登入按鈕
忘記密碼連結
註冊連結
```

登入成功後：

```text
□ 若從商品加入購物車導來，回到原商品或購物車
□ 若一般登入，導向首頁或會員中心
□ 後端設定 HttpOnly Secure Cookie
□ 寫入 UserLoginLogs
```

---

## 3. 後台管理登入

欄位：

```text
帳號 / Email
密碼
登入按鈕
忘記密碼連結
```

後台登入成功後必須檢查：

```text
□ UserType 是否為 Admin 或 Staff
□ 帳號是否啟用
□ 是否有後台登入權限
□ 是否需要 MFA 或額外驗證
□ 寫入 UserLoginLogs
```

後台登入失敗不可透露：

```text
帳號不存在
密碼錯誤
角色不符
```

統一顯示：

```text
帳號或密碼錯誤，請重新確認。
```

---

## 4. 註冊頁

欄位：

```text
姓名
Email
手機
密碼
確認密碼
同意服務條款
註冊按鈕
```

規則：

```text
□ 密碼強度檢查
□ Email 不可重複
□ 手機格式檢查
□ 密碼與確認密碼一致
□ 不可讓前端決定 UserType
□ 註冊只建立 Customer，不可建立 Admin / Staff
```

---

## 5. 忘記密碼頁

流程：

```text
1. 使用者輸入 Email
2. 後端產生短效重設 Token
3. 寄送重設密碼信
4. 使用者點擊連結進入重設頁
5. 設定新密碼
6. 舊 Token 失效
```

資安：

```text
□ 不透露 Email 是否存在
□ Token 有效期限短
□ Token 只能使用一次
□ 重設成功寫入安全紀錄
□ 忘記密碼 API 加 Rate Limit
```

---

## 6. 社群登入按鈕處理

`login.html` 內有 Google / GitHub 按鈕。若目前尚未實作第三方登入，建議：

```text
□ 先移除
或
□ 顯示但標註「暫未開放」
```

不要讓畫面顯示可用，但實際無法登入。

---

## 7. 本章總結

登入頁可以共用視覺風格，但前台會員登入與後台管理登入必須分開路由、分開 Controller Action、分開登入後導向，且後台必須額外檢查 UserType、Role 與 Permission。
