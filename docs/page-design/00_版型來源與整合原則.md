# 00｜版型來源與整合原則

## 1. 目前版型來源

目前提供的版型檔案包含：

```text
index.html                  後台 Dashboard / 儀表板版型
analytics.html              後台數據分析版型
projects.html               後台看板 / 任務式管理版型，可改造成商品或訂單流程管理
inbox.html                  後台訊息 / 通知 / 客服訊息版型
settings.html               後台設定 / 帳號 / 系統偏好版型
login.html                  登入頁面版型
about-templatemo.html        前台關於 / 品牌介紹 / 商品展示區塊參考

templatemo-daynight-style.css

templatemo-daynight-script.js
```

這些檔案採用 DayNight Admin 風格，具有：

```text
□ 淺色 Snow 模式
□ 深色 Carbon 模式
□ 上方導覽列
□ 手機選單
□ 卡片式區塊
□ Stats Grid
□ 表單樣式
□ 表格樣式
□ Kanban 看板
□ Inbox 分欄
□ Settings 表單
□ Login Card
```

## 2. 版型整合目標

本專案不是單純展示 Template，而是要把版型轉成正式電商 MVC 頁面。

整合後應達成：

```text
□ 前台顧客可以在未登入狀態瀏覽商品樣式
□ 前台顧客登入後可以加入購物車、結帳、查詢訂單
□ 後台管理員登入後才可以看到 Dashboard 與數據分析
□ 前台頁面不顯示營收、轉換率、後台指標
□ 後台頁面依 Role / Permission 顯示管理功能
□ HTML 假資料逐步替換成 ViewModel 或 API 資料
□ CSS / JS 放入 wwwroot，不散落在 View 中
```

---

## 3. 不能直接照搬的地方

| 版型內容 | 正式系統處理方式 |
|---|---|
| `index.html` 的營收、訂單、轉換率 | 只能放後台 Dashboard，不可放前台首頁 |
| `analytics.html` 的數據分析 | 只給後台管理者使用 |
| `projects.html` 的專案看板 | 可改成商品管理、訂單流程、出貨流程或任務看板 |
| `inbox.html` 的訊息 | 可改成客服訊息、站內通知、系統警示 |
| `settings.html` 的設定 | 可拆成帳號設定、系統設定、通知設定、安全設定 |
| `login.html` 的社群登入按鈕 | 未實作第三方登入前先移除或標記未啟用 |
| HTML 中的假連結 | 必須改成 MVC Route / Tag Helper |
| HTML 中的假資料 | 必須改成 ViewModel / DTO |
| JavaScript 的 `innerHTML` 動態插入 | 不可用於未清理使用者輸入，避免 XSS |
| CDN 資源 | 正式上線應評估本地化、SRI 或版本鎖定 |

## 4. 版型整合分層

```text
Views
  ↓
ViewModel
  ↓
Controller
  ↓
Service
  ↓
Repository
  ↓
MSSQL
```

頁面切版只處理畫面，不處理核心交易規則。

例如：

```text
商品價格顯示：ViewModel 提供
是否可購買：Service 判斷
加入購物車：Controller 呼叫 CartService
建立訂單：OrderService 使用 Transaction
後台營收統計：DashboardService 組合資料
```

---

## 5. 檔案轉換原則

```text
HTML 的 <head> 共用內容 → Shared Layout
HTML 的 top-nav → Shared Header 或 Admin Header
HTML 的 mobile-menu → Shared Mobile Menu Partial
HTML 的 main-content → 各頁 View Content
CSS → wwwroot/css/daynight.css
JS → wwwroot/js/daynight.js
假資料 → ViewModel
連結 href="index.html" → asp-controller / asp-action
```

---

## 6. 本章總結

DayNight 版型可以當作視覺基礎，但整合進正式電商網站時，必須拆成前台與後台兩套使用情境。前台重點是商品展示與購物流程，後台才顯示 Dashboard、數據分析、管理工具與稽核功能。
