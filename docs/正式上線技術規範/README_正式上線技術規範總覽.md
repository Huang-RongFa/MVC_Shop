# 正式上線技術規範總覽

## 1. 文件目的

`docs/MSSQL` 與 `docs/MVC` 已經規劃資料庫、後端分層、API、前端流程與基本資安檢查。若要讓全端電商網站正式上線，還需要補上營運環境、網路安全、部署流程、監控告警、備份還原、金流合規與驗收標準。

本資料夾用來補齊「正式上線前一定要確認的技術規範」。

---

## 2. 現有文件是否足以上線

結論：目前文件已具備良好的開發規劃基礎，但還不能單獨視為完整正式上線規範。

已具備：

```text
□ MSSQL 資料表規劃
□ ERD 關聯整理
□ 後端 API 與資料表對應
□ ASP.NET Core Web API 分層規劃
□ Cookie / Token、CORS、Middleware 基本概念
□ OWASP 基本資安檢查
□ 資料庫部署檢查清單
```

仍需補強：

```text
□ 網域、DNS、TLS、HSTS
□ 反向代理與正式網路拓樸
□ CI/CD 與部署回滾
□ 機密管理與環境隔離
□ Log、Metric、Trace、告警
□ 備份、還原演練、災難復原
□ 效能、壓測、容量規劃
□ 金流、物流、第三方 API 合規
□ 個資、Cookie、CSRF、資料保存週期
□ 上線前驗收與上線後觀察
```

## 4. 初學者理解方式

可以把正式上線想成三層：

```text
程式能跑
  ↓
系統安全穩定
  ↓
發生問題時能追蹤、修復、還原
```

開發文件通常回答「功能怎麼做」；正式上線規範則回答「網站真的開放給使用者後，如何安全、穩定、可維護地運作」。
