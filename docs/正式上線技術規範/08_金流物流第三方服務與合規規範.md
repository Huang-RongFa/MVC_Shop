# 08｜金流、物流、第三方服務與合規規範

## 1. 本章目的

電商系統正式上線時，金流與物流是高風險流程。測試環境、正式環境、Webhook、退款與敏感資料都必須規劃清楚。

---

## 2. 金流規範

```text
□ 測試金流與正式金流金鑰分開
□ 正式金鑰不進 Git
□ 付款 Callback 驗證簽章
□ 付款 Callback 可重試
□ 同一付款事件不可重複處理
□ 金流交易編號需保存
□ 付款失敗原因需保存
□ 退款流程需權限控管
```

---

## 3. 敏感卡片資料

建議不要讓自己的系統保存信用卡完整卡號、CVV / CVC 或磁軌資料。

建議做法：

```text
□ 使用第三方金流頁面或金流 Token
□ 自家資料庫只保存付款狀態與交易編號
□ 不保存 CVV / CVC
□ 不在 Log 中記錄卡片資料
□ 不在錯誤訊息中顯示金流敏感資料
```

---

## 4. 物流規範

```text
□ 測試物流與正式物流金鑰分開
□ 出貨單號需保存
□ 物流狀態更新需留紀錄
□ 出貨前檢查訂單狀態
□ 出貨前檢查付款狀態
□ 出貨流程需要權限控管
```

---

## 5. Webhook 與重複事件

第三方服務可能重送通知，所以後端要支援冪等性。

初學者可以把冪等性理解成：「同一個通知送來很多次，系統結果仍然只處理一次」。

檢查：

```text
□ 保存第三方事件 ID
□ 重複事件不重複扣庫存
□ 重複付款通知不重複建立付款
□ 重複出貨通知不重複修改訂單
```

---

## 6. 本章總結

金流與物流不能只看 API 串接成功，還要確認正式與測試環境隔離、Webhook 安全、敏感資料不落地、重複事件不造成重複扣款或出貨。
