# 07｜效能、壓測、快取與容量規劃規範

## 1. 本章目的

電商網站可能遇到活動促銷、尖峰流量或大量查詢。正式上線前，需要知道系統能承受多少流量，瓶頸在哪裡。

---

## 2. 效能目標

可先設定基本目標：

```text
商品列表 API：平均 500ms 內
商品詳細 API：平均 500ms 內
登入 API：平均 800ms 內
建立訂單 API：平均 1 秒到 2 秒內
後台查詢 API：平均 1 秒內
```

實際數字要依伺服器規格與需求調整。

---

## 3. 壓測項目

```text
□ 首頁載入
□ 商品列表查詢
□ 商品關鍵字搜尋
□ 商品詳細頁
□ 登入
□ 加入購物車
□ 建立訂單
□ 付款 Callback
□ 後台訂單查詢
```

---

## 4. 資料庫效能

檢查：

```text
□ 常查詢欄位有 Index
□ 訂單列表依時間查詢有效率
□ 商品列表分頁查詢
□ 不一次回傳大量資料
□ 避免 N+1 查詢
□ 大型報表避免影響交易資料庫
```

---

## 5. 快取策略

適合快取：

```text
商品分類
商品列表部分查詢
促銷活動
首頁資料
靜態圖片
前端 JS / CSS
```

不適合隨便快取：

```text
庫存數量
付款狀態
訂單狀態
個人資料
權限資料
```

---

## 6. CDN 規劃

前端靜態檔案與商品圖片適合放 CDN：

```text
□ JS / CSS / Image 使用 Cache-Control
□ 檔名帶 hash 避免舊快取
□ 商品圖片可壓縮
□ 圖片使用合適尺寸
```

---

## 7. 本章總結

效能規劃不是最後才處理，而是 API、資料庫、前端資源與快取一起看。正式上線前，至少要測過商品查詢、登入、下單與付款 Callback。
