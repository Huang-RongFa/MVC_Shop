# 02｜環境分離、組態與機密管理規範

## 1. 本章目的

正式電商系統不應只有一個環境。開發、測試、正式環境要分開，避免測試資料、測試金流或開發機密誤用到正式環境。

---

## 2. 建議環境

| 環境 | 用途 | 注意事項 |
|---|---|---|
| Development | 本機開發 | 可使用測試資料，不連正式金流 |
| Staging | 上線前驗收 | 盡量接近正式環境 |
| Production | 正式營運 | 嚴格控管權限、資料、機密 |

---

## 3. 組態管理

不同環境應使用不同設定：

```text
appsettings.Development.json
appsettings.Staging.json
appsettings.Production.json
```

但正式機密不要直接寫進檔案。

正式環境應由下列方式提供：

```text
環境變數
User Secrets
Key Vault / Secret Manager
CI/CD Secret Variables
Docker / Kubernetes Secret
```

---

## 4. 機密資料清單

```text
□ MSSQL 連線字串
□ Cookie / Token 簽章金鑰
□ 金流 API Key
□ 物流 API Key
□ SMTP 密碼
□ 雲端儲存金鑰
□ 第三方登入 Client Secret
```

這些資料不應進入 Git。

---

## 5. 機密輪替

正式環境要規劃 Key Rotation。

```text
□ Cookie / Token 簽章金鑰可輪替
□ 金流金鑰可更換
□ 資料庫帳號密碼可更換
□ 離職人員權限可撤銷
□ API Key 外洩時有應變流程
```

---

## 6. 權限最小化

```text
□ 應用程式資料庫帳號只給必要權限
□ 開發人員不直接操作正式資料庫
□ 正式伺服器登入需留紀錄
□ 後台管理員角色分級
□ 金流退款權限需額外限制
```

---

## 7. 本章總結

環境分離是避免事故的第一道防線。正式上線前，要確認 Development、Staging、Production 的資料庫、金流、物流、Cookie / Token 簽章金鑰、CORS 網域與 Log 設定都彼此分離。
