# 04｜後台頁面設計清單

## 1. 後台設計目標

後台頁面提供管理員與員工操作電商營運資料。所有後台頁面都必須登入，並依 Role / Permission 控制是否可看、可新增、可修改、可刪除或可匯出。

後台才可以顯示 Dashboard、數據分析、訂單統計、營收、轉換率與管理操作。

---

## 3. Dashboard 設計

Dashboard 可以使用 `index.html` 的 Stats Grid 與圖表區塊，但資料要改成電商營運指標。

建議顯示：

```text
□ 今日營收
□ 今日訂單數
□ 待出貨訂單
□ 待退款申請
□ 低庫存商品
□ 付款失敗數
□ 最近訂單
□ 最近後台操作
□ 系統警示
```

不應顯示：

```text
□ 與電商無關的專案任務假資料
□ Template 預設 Alex / Sarah 等假人名
□ 靜態假營收作為正式資料
```

---

## 4. 數據分析設計

`analytics.html` 可改成後台分析頁。

可顯示：

```text
□ 營收趨勢
□ 訂單趨勢
□ 商品銷售排行
□ 分類銷售排行
□ 付款成功率
□ 退款率
□ 會員成長
□ 訪客與轉換率
```

權限：

```text
Analytics.Read
Dashboard.Read
```

---

## 5. 商品管理設計

商品管理可以使用 Table + Card，也可以把 `projects.html` 的 Kanban 改成商品狀態流程：

```text
草稿
待審核
已上架
已下架
```

商品表格欄位：

```text
商品圖片
商品名稱
分類
SKU 數量
售價範圍
狀態
建立時間
最後更新
操作按鈕
```

操作：

```text
查看
新增
修改
上下架
管理 SKU
管理圖片
```

## 6. 訂單與出貨設計

訂單列表欄位：

```text
訂單編號
會員
訂單金額
付款狀態
訂單狀態
出貨狀態
建立時間
操作
```

訂單詳細需顯示：

```text
訂單主檔
訂單明細
付款紀錄
出貨紀錄
退款紀錄
狀態歷史
後台操作紀錄
```

重要：付款成功只代表 `Paid`，不等於自動出貨。出貨確認後才扣實際庫存。

## 8. 本章總結

後台頁面可以使用 DayNight Admin 原本的 Dashboard、Analytics、Inbox、Projects、Settings 版型，但必須全部轉換成電商管理語意，並加入後端權限、稽核與正式資料來源。
